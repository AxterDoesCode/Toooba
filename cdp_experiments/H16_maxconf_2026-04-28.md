## Mechanism

H7/H15's PrefetchIssue offset-selection loop:

```bsv
for (Integer i = 14; i >= 0; i = i - 1) begin
    if (entry.conf[i] >= threshold) begin
        bestRelOffset = i - 7;        // ← unconditional overwrite
        ...
    end
end
```

Bluespec last-write-wins → the LAST passing iteration wins. Loop runs
i=14→0, so `bestRelOffset` ends up at the smallest passing i (most
negative relOffset), independent of confidence value. With 2-bit conf
in H15 more offsets cluster at saturation → arbitrary tail-pick fires
more often → H15's +0.236% health regression.

H16 adds a `> bestConf` comparison so the picker actually uses confidence
for ranking:

```bsv
Bit#(2) bestConf = 0;
for (Integer i = 14; i >= 0; i = i - 1) begin
    Bit#(2) thisConf = entry.conf[i];
    if (thisConf >= threshold && thisConf > bestConf) begin
        bestRelOffset = i - 7;
        bestConf = thisConf;
        ...
    end
end
```

This compiles to a 15-stage combinational max-tree (each stage's
bestConf is sequentially threaded through the unrolled chain). No extra
cycles. Strict superset of H15 in mechanism; inherits the 1.92 KB BRAM
saving.

## Mechanism analysis: health (the big winner)

| metric | H7 | H15 | H16 |
|:---|---:|---:|---:|
| prefetch issued | 12,240 | 11,886 | 11,431 |
| prefetchHit (already L1) | 6,350 | 5,850 | **3,619** (−43%) |
| prefetchMiss (real fetch) | 4,342 | 4,465 | **7,030** (+62%) |
| usefulPrefetch | 3,332 | 3,422 | **6,265** (+88%) |
| lateUsefulPrefetch | 1,117 | 1,150 | **239** (−79%) |
| **timely useful** | 2,215 | 2,272 | **6,026** (+172%) |

The max-conf picker fundamentally changes which offsets get picked:
- Selects offsets NOT already in L1 (prefetchHit drops 43%)
- Selects offsets that match real patterns (useful jumps 88%)
- Arrives in time more often (lateUseful drops 79%)
- Fewer total issues but +172% timely useful

Health was traditionally CDP's middle-tier bench. H16 makes it a
co-headline result alongside patricia.

## Mechanism analysis: treeadd (the regression)

| metric | H7 | H16 | Δ |
|:---|---:|---:|---:|
| prefetch issued | 15,324 | 19,878 | +30% |
| prefetchHit (already L1) | 13,310 | 19,002 | **+43%** |
| prefetchMiss | 1,680 | 776 | −54% |
| usefulPrefetch | 1,612 | **726** | −55% |
| timely useful | 1,580 | 653 | −59% |

Opposite story to health. Treeadd's hot PCs have a "best" offset that's
already loaded in L1 by demand-driven traffic. H7's last-write-wins
spread issued prefetches across multiple offsets — some of those
"second-best" offsets weren't already in L1 and provided real benefit.
H16's max-conf picker homes in on the single highest-conf offset which,
for treeadd, is "the line we'd load anyway."

This explains earlier `cdp_insight_treeadd_slowdown.md` observations:
treeadd's pattern doesn't reward sharper prefetcher selectivity, it
rewards *spread* across offsets to catch the second-most-likely
candidates. H16 removes the spread. Treeadd is now the lone bench
where H16 underperforms H7.

Net cost on geomean: treeadd's +0.43% × (1/8) weight ≈ +0.054 pp,
fully eaten by H16's gains elsewhere (health alone gave −0.10 pp).

## Mechanism analysis: patricia (still the anchor)

H16 makes patricia even better: −12.31% vs NoPref2 (was −12.06% in H7).
The dominant 84e0 PC has a single saturated offset (per
`cdp_insight_dram_bypass_unique_to_patricia.md`); max-conf picks the
right offset more reliably and slightly faster than H7's tail-pick
ever did.

## Next directions

1. **H16-tie-break sweep**: try `>=` instead of `>` (ties go to last
   encountered = lowest i = most negative offset, matching H7's bias).
   Could close the treeadd regression while keeping health gains.
2. **H17: H16 + treeadd-style multi-issue?** Issue top-K (K=2 or 3)
   highest-conf offsets, not just top-1. Recovers treeadd's spread
   benefit while keeping max-conf for the others. Adds candidate-FIFO
   pressure on the prefetch path.
3. **Continue BRAM shrink**: filter `lineAddr` is the next 7.25 KB
   target. With H16 as the new reference, the BRAM-vs-perf trade-off
   for hashing the filter tag now has a clean baseline.
