# Exp 6: decayInterval 16 → 64 (2026-04-20) — **FIRST CLEAR WIN**

## Change
Single edit, pure parameter: `Prefetcher_top.bsv` `Parameter#(16) decayInterval`
→ `Parameter#(64)`. Baseline CDP.bsv (Exp 4/5 reverted). Slows the confidence-
decay mechanism from "fire every 16 cycles" to "fire every 64 cycles".
Each fire still picks one random PC-table entry via LFSR and decrements all
15 confidence counters by 1; the LFSR just fires 4× less often.

## Verdict
**Universal win**. Every benchmark improved cycles. Patricia's +4.2% gain is the
first experiment to beat baseline on patricia, and it's the largest single
change observed in either direction. IPC went up on all 5 benchmarks too
(patricia crosses 1.0 IPC into actively-benefiting-from-prefetch territory).

## Why it works — hypothesis

The baseline decay at every 16 cycles was **too aggressive**. With pcTableSize=1024,
each PC-table entry gets hit by decay roughly every `decayInterval × pcTableSize
= 16,384` cycles on average; each hit decrements every counter by 1. Over a 1.4M-
cycle patricia run this means ~85 decay events per entry, so each conf value
drops by ~85 over the run. Since conf is 3 bits (0..7), entries saturate-and-
collapse many times.

Moving to decayInterval=64 means each entry only gets ~21 decay events in the
same run — patterns keep their learned conf-above-threshold state ~4× longer,
and more patterns stay "alive" at threshold at any given time. Accuracy stays
in the same range (most benchmarks +0-6pp), and with more patterns firing the
total useful-prefetch count goes up on every benchmark except treeadd.

Interestingly, treeadd's issued count went DOWN slightly (19897 → 19666) while
useful went UP (3318 → 3345) — even for treeadd the slower decay let specific
patterns stabilize, issuing FEWER but MORE ACCURATE prefetches.
