CDP Relative Policy:
**Training (building confidence)**

When a cache line arrives on a MISS, each word is checked for same-page pointer candidates (VPN match). For each candidate at absolute position `i`:
- Its vaddr is XOR-folded into a training table index
- If no entry exists, one is created storing the PC hash, the relative offset `i - dataSel` (where `dataSel` is the miss word position in this line), and the full vaddr for collision detection
- If an entry already exists AND this candidate is the word that was actually missed (`missedOnThisVaddr`), the pcTable confidence counter for the stored relative offset is saturating-incremented

**Prefetch issue (two paths)**

1. **On MISS** — one pcTable lookup is issued per incoming line using the request's PC hash. If any relative offset has confidence ≥ 3, the value at `line[hitOffset + relOffset]` is used as the prefetch target, bounds-checked to ensure the resulting absolute offset stays within 0–7, and VPN-validated before enqueuing
2. **On HIT** — same pcTable lookup and same selection logic, triggered from `reportAccess`

**Confidence decay**

Every `decayInterval` cycles a randomly selected pcTable entry has all 15 of its confidence counters saturating-decremented by 1, preventing stale patterns from persisting indefinitely.
