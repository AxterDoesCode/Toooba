CDP Relative Policy:
**Training (building confidence)**

When a cache line arrives on a MISS, each word is checked for same-page pointer candidates (VPN match). For each candidate at absolute position `i`:
- Its vaddr is XOR-folded into a training table index
- If no entry exists, one is created storing the PC hash, the relative offset `i - dataSel` (where `dataSel` is the miss word position in this line), and the full vaddr for collision detection
- If an entry already exists AND this candidate is the word that was actually missed (`missedOnThisVaddr`), the pcTable confidence counter for the stored relative offset is saturating-incremented

**Prefetch issue (two paths)**

1. **On MISS** — one pcTable lookup is issued per incoming line using the request's PC hash. If any relative offset has confidence ≥ 3, the value at `line[hitOffset + relOffset]` is used as the prefetch target, bounds-checked to ensure the resulting absolute offset stays within 0–7, and VPN-validated before enqueuing
2. **On HIT** — same pcTable lookup and same selection logic, triggered from `reportAccess`

**Confidence decay**

Every `decayInterval` cycles a randomly selected pcTable entry has all 15 of its confidence counters saturating-decremented by 1, preventing stale patterns from persisting indefinitely.

Summary of policy 10 April
Here's how the full pipeline works end-to-end:

---

## CDP Stateful Relative — Prefetch Policy Overview

### Core Idea
The prefetcher learns that certain **load instructions** (identified by `pcHash`) tend to fetch cache lines that **contain pointer-like values**, and that those pointers are typically found at a **consistent relative offset** from the word that caused the miss. When confidence is high enough, it speculatively prefetches the cache line pointed to by the value at that offset.

---

### Data Structures

| Structure | Type | Purpose |
|---|---|---|
| **Training Table** | 4-way set-assoc BRAM, keyed by vaddr | Remembers: "this vaddr was seen as a pointer in a line loaded by `pcHash`, at `relOffset` from the miss word" |
| **PC Table** | Flat BRAM, keyed by `hash(pcHash)` | Stores a confidence vector `Vector#(15, Bit#(3))` over relative offsets −7..+7 for each load PC |

---

### Training Pipeline (on every L1 miss fill)

When an L1 miss resolves and the filled cache line arrives (`reportIncomingCacheLine`):

1. **Training trigger (slot 0)**: Reconstruct the virtual miss address `{vpn, pageOffset(paddr)}` and look it up in the training table.
   - **Hit**: This address was previously seen as a pointer value in some other line, stored there by a load with `ttRdResp.pcHash` at `ttRdResp.lineOffset`. → Saturating-increment that confidence counter in the PC table entry for that `pcHash`.
   - **Miss**: Address has never been seen as a pointer — nothing to do.

2. **Candidate collection (slots 1–8)**: Scan all 8 words of the incoming cache line. Any word whose upper `matchBits` bits of VPN match the miss address's upper `matchBits` is treated as a candidate pointer.
   - **Training table miss**: This is a new candidate — write `{storedVaddr=candVaddr, pcHash=currentPcHash, relOffset=candidatePos − missPos}` into the training table, so that if this address is ever accessed, we can train.
   - **Training table hit**: Already recorded — skip.

---

### Prefetch Issue Pipeline (on every L1 hit or miss load)

On `reportAccess` (HITs) and `reportIncomingCacheLine` (MISSes), a `PrefetchIssue` lookup is enqueued for the current PC's entry in the PC table. When that response arrives:

- Look through the confidence vector for any offset with confidence ≥ 3.
- Compute `absTarget = missWordOffset + relOffset` — the absolute word position in the line to read the prefetch candidate from.
- If `absTarget` is within 0–7 and the word there passes the `matchBits` upper-VPN check → enqueue the candidate vaddr for **TLB translation**.
- TLB responds with a physical address → enqueue to `nextCandidateBuffer`.
- `getNextPrefetchAddr` dequeues and issues the prefetch.

---

### Pointer Detection (`matchBits` parameter = 16)

A value in a cache line is considered a candidate pointer if its upper 16 bits of VPN match the miss address's upper 16 bits of VPN. This covers a ±8MB address region around the miss, allowing **cross-page** pointer detection (previously only same-page pointers were found by requiring full VPN equality).

---

### Confidence Decay

An LFSR fires every `decayInterval` cycles, picks a random PC table index, and saturating-decrements all 15 confidence counters in that entry by 1. This evicts stale prefetch patterns over time without needing to invalidate training table entries.

---

### What's *Not* Done

- **Store misses** are ignored everywhere — only loads train and trigger prefetches.
- **Prefetch hits** don't trigger further prefetch issue (only demand loads do via `reportAccess`).
- The training table has **no decay** — entries persist until evicted by the 4-way replacement policy. Only the PC table decays.
